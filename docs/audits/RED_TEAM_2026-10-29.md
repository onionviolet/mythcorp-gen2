Type: AUDIT. Audience: HUMAN + AGENT. Findings, not accepted decisions. No code,
config or deployment changed.

Scope: source review of the public attack surface (middleware and site lock,
`/api/upload`, `/api/delete`, `/api/img`, `/api/sky`, `src/lib/upload/*`),
passive GETs and HEADs against mythcorp.org and i.mythcorp.org, public DNS and
whois for mythcorp.com, and `npm audit --omit=dev`. No authenticated requests,
uploads, delete attempts, fuzzing or load testing. Also red-teams the landing
and AI-age ideas proposed the same day.

## What already holds up

Upload keys (192-bit) and delete tokens (128-bit) are random and stored hashed.
The key is checked before the body is read. File type comes from magic bytes,
the served content type comes from the allowlist, `nosniff` is set and images
live on a separate host. Object keys are shape-validated before they reach the
S3 path. Delete is POST-only and answers the same for a wrong token and a
deleted image. `/api/sky` never returns or logs coordinates.

### RT3 applicability on OpenNext/Workers

Each advisory read through `gh api /advisories/<id>`. 15.5.28 is past every
patched version below; `npm audit --omit=dev` no longer lists `next` itself.

- GHSA-2464-fhr4-w9xw (critical, image optimizer RCE): does not apply. The bug
  is in `sharp` on glibc Linux. OpenNext's worker answers `/_next/image` with its
  own handler (`@opennextjs/cloudflare` `templates/images.js`), which returns the
  original bytes when no `IMAGES` binding exists, and `wrangler.jsonc` defines
  none. Next's optimizer and `sharp` never run in production. Patched anyway.
- GHSA-4jqv-mc3x-m676 (SSG/ISR cache poisoning): does not apply. Pages Router
  only; this repo has no `pages/` directory.
- GHSA-mcj8-r9mp-w47p (SSG/ISR cache poisoning): does not apply. Needs a
  root-level catch-all page; `src/app` has none.
- GHSA-p3m5-59mp-jv5r (Server Actions DoS): does not apply. No `"use server"`
  anywhere in `src`.
- Bundled `postcss` advisories inside `next`: build-time only, no runtime path.
  Clearing them needs Next 16, which is a major jump and was not taken.
- Still in `npm audit --omit=dev`, untouched: `wrangler`/`miniflare`/`sharp`
  (local tooling), `proxy-addr`, `body-parser`, `qs`, `picomatch`,
  `brace-expansion`, `fflate`. None ships in the Worker's request path as far as
  read; not individually verified.
- **Deploy blocker, independent of this upgrade.** `@opennextjs/aws` refuses to
  build any Next major more than two years past release
  (`NEXT_RELEASE_DATES[15] = "2024-10-21"`), so `npm run deploy` fails from
  2026-10-21 on, with 15.5.25 too. A local `opennextjs-cloudflare build
  --dangerouslyUseUnsupportedNextVersion` on 15.5.28 completed. Weibao decides
  between adding that flag to the deploy script and moving to Next 16.

### RT5 notes

`src/lib/upload/strip.ts`, no pixel re-encoding. JPEG keeps JFIF, Adobe and ICC
segments, drops every other APPn, comments and anything after the first EOI
(iPhone MPF gain maps), and writes back EXIF Orientation alone. PNG drops
`tEXt`, `zTXt`, `iTXt`, `eXIf`, `tIME`. WEBP drops `EXIF` and `XMP ` and clears
their VP8X flags. A file the walker cannot parse is rejected with 400, never
stored as-is. GIF passes through. PNG and WEBP lose their orientation tag;
browsers rarely honor it there. Fixtures (Pillow, with a GPS IFD) and their
generator sit in `src/lib/upload/fixtures/`. Already-stored objects keep their
metadata; nothing was re-processed.

### RT6 notes

Enforced: HSTS `max-age=31536000`, `nosniff`, `strict-origin-when-cross-origin`,
`X-Frame-Options: SAMEORIGIN`, `Content-Security-Policy: frame-ancestors 'self'`,
and a Permissions-Policy that denies camera, microphone, geolocation, payment,
USB and topics (clipboard stays allowed for copy buttons). Everything else is
`Content-Security-Policy-Report-Only`, with no reporting endpoint, so violations
show only in the browser console. Static assets served straight from Workers
assets skip the middleware and get none of these; a `public/_headers` file would
cover them. HSTS `includeSubDomains` and `preload` are hard to reverse and left
for Weibao.

### RT4: Cloudflare dashboard steps (not applied)

The Free plan allows one rate limiting rule, a 10 second counting period and
mitigation timeout, counting by IP, and only the Path and Verified Bot fields
(Cloudflare docs, read 2026-10-29). Pro and up allow longer windows and a
custom 429 body.

1. Cloudflare dashboard, zone `mythcorp.org`, Security, Security rules.
2. Create rule, Rate limiting rules. Rule name: `api flood`.
3. Field `URI Path`, operator `starts with`, value `/api/`.
   Expression: `starts_with(http.request.uri.path, "/api/")`.
4. Leave "Also apply rate limiting to cached assets" on.
5. With the same characteristics: IP (the only Free option).
6. When rate exceeds: 20 requests per 10 seconds. The home page polls
   `/api/sky` a few times per load, so this leaves room for honest visitors.
7. Then take action: Block. Duration: 10 seconds.
8. Deploy. Image traffic (`i.mythcorp.org/<key>.png`) has no `/api/` path at the
   edge, so the rule does not touch it.
